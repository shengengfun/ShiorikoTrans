feat(translate,summarize): run models locally, rebuild the summary page

Local inference used to mean "install llama.cpp and start llama-server
yourself", which is why local translation ended in
`error sending request for url (http://127.0.0.1:8080/...)`. The app now
owns that runtime and the summary page is built on top of it.

Engine
- new Rust module (llama.rs): status / install / start / stop commands,
  resolves a CPU llama.cpp build from the GitHub release API, extracts it
  with the system tar (no new crate), serves the selected GGUF on the
  configured port and kills the child on exit
- shared frontend layer (local-engine.ts): probe, auto-start, model lookup;
  translation, summarisation and the settings "test" buttons all use it
- translation and summarisation now default to the built-in engine with a
  1 GB model instead of a 4.4 GB download

Summary page
- "Summarize" action on the transcript page, plus an option to open the
  summary tab automatically when a transcription finishes
- the summary tab is reachable without an existing summary and shows an
  empty state with a summarize button
- long transcripts are summarised in chunks and merged, so a small local
  model can handle a two-hour recording
- prompt presets (default / short abstract / key points / minutes / notes),
  restore default, chunk size, temperature, local model picker
- a template without `%s` no longer drops the transcript silently

Settings
- shared local engine panel and model list (download, select, pick a GGUF
  from disk) for both translation and summarisation

Validation: tsc 0 errors, vitest 10/10, vite build ok, cargo check clean.
