# ShiorikoTrans v1.0.9

设置界面整体重做：加了搜索、分组与子标签，一屏能看到更多选项，并补齐了转录方向、字幕预设、批量默认值、硬件加速、日志诊断等设置。同时**「最近」不再只记住文件，而是把转录内容一起保存**——重新打开即可恢复文本，源文件被移动或删除也照样能看。

## 下载

| 平台 | 文件 | 说明 |
| --- | --- | --- |
| Windows | `ShiorikoTrans_1.0.9_x64-setup.exe` | **全量版**。内置 ffmpeg，装完即用，体积大一些 |
| Windows | `ShiorikoTrans_1.0.9_x64-setup-slim.exe` | **精简版**。不含 ffmpeg（约 83 MB 下载量省掉），首次转录音频/视频时提示并在应用内下载，也可以自己在设置里手动下载 |
| macOS | `ShiorikoTrans_1.0.9_<arch>.dmg` | 打开后把 App 拖进 Applications |
| Linux | `ShiorikoTrans_1.0.9_amd64.deb` / `ShiorikoTrans-1.0.9-1.x86_64.rpm` | Debian / Ubuntu、Fedora / RHEL |

两个 Windows 包功能完全一致（引擎、模型、界面都相同），只差 ffmpeg 是否内置。

## 本版改动

### 「最近」现在记住的是转录内容，不只是文件

- 转录完成后（含随后的翻译、摘要、手动修改）会把**文本内容一并保存**到本地，「最近」列表里点一下就直接恢复原文，不必重新跑一遍。
- 列表里能看到每条记录**有多少段**，设置页还会显示**转录开头的一句话**，一眼就能认出是哪一份。
- **源文件被移动或删除也能打开**：内容已在本地，打开后只是提示源文件不在了，并把输入区清空，避免误点转录。
- 录音只留在临时目录、或者从链接下载的音频被系统清理后，过去会留下「点不开的死条目」——现在这类条目会被识别并标记；如果内容已保存，仍然可以正常打开。
- 条目支持**单条删除**、**一键清空**，以及只清理「文件没了且确实没有内容」的失效项。转写进行中会拒绝打开历史，避免把正在跑的会话覆盖掉。

### 设置界面重做

- **搜索**：左上角搜索框（`Ctrl+F` 直达），输入关键词即可跨全部分节搜索，回车直接跳到该设置项并高亮闪烁，中英文关键词都能命中（比如「声音 / sound」）。
- **结构**：分组导航 + 分节内子标签（通用 / 转录 / 模型 / 翻译 / 硬件加速 / 高级 等），窗口较宽时自动排成两列，同样一屏能看到更多设置；弹窗更大、`Esc` 关闭。
- **新的行样式**：一个分组一张卡片、行内直接给出「名称 + 一句说明 + 右侧开关/选择」，比原来「一个设置一张卡片」紧凑很多。
- **原有的每一项设置都保留**，并补齐了：
  - 通用：**转录文本方向**（阿拉伯语/希伯来语等从右到左语言）、**字幕预设**（一键打开词级时间戳 + 句长 32 + SRT）、导出格式合并到一处；
  - 转录：**批量转写默认值**（包含子文件夹 / 跳过已存在 / 输出到源文件目录）从首页搬进设置，ffmpeg 状态与下载按钮也在这里；
  - **硬件加速**独立成分节：设备选择、强制 CPU、Vulkan 设备索引、量化提示、详细诊断、设备检测与 Vulkan 信息；
  - 高级：查看日志、生成诊断报告、复制日志、打开日志/临时目录、重置应用；
  - 重置默认设置与重置应用都改成了**点击两次确认**，避免误触。
- 界面文案补齐多语言（新增 96 条词条），此前硬件加速与日志区里写死的中文已全部纳入翻译。

### 修复

- 修复「最近」列表里的条目点开没有任何反应的问题（写入时机上的竞态导致选择被页面重置覆盖）。
- 修复构建脚本在 `bundle/nsis` 目录里存在历史安装包时会误报失败的问题。

## 已知问题 / 升级说明

- 精简版首次处理音视频文件需要联网下载 ffmpeg（约 83 MB，一次即可）；全量版无此需求。
- 「最近」的转录内容保存在应用配置目录（`transcripts.json`），最多保留 12 条、约 600 万字符；超出后最旧的记录会保留条目但不再保留内容（列表会标注「仅文件」）。
- Linux 的 deb / rpm 依赖系统 ffmpeg 包（发行版仓库里已有），不区分精简 / 全量；macOS 目前只提供全量 dmg。
- 批量页的转写队列仍是页面级状态，切页会中断队列显示（尚未改造）。
- 上游预编译的 `sona` 二进制不含 SenseVoice 引擎（本仓库构建的 sidecar 含），用 CI 工作流构建的包可能无法使用 SenseVoice，其余模型不受影响。
- macOS 包未签名 / 未公证，首次打开若被 Gatekeeper 拦，右键 →「打开」即可。
