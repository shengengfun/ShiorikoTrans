# ShiorikoTrans v1.0.13

这一版主打**速度**：新增「高性能模式」，自动识别 CPU 核心、内存与显存，按硬件推导并发进程数；批量转写可以多个文件同时跑，长音频还会按静音处切片并行转写。

## 本版改动

### 🚀 高性能模式（设置 → 硬件加速 → 高性能）

新增一个内置开关，**默认开启**，并会按硬件自动推导运行参数：

- **自动识别硬件**：CPU 物理/逻辑核心、内存、显卡及显存（`nvidia-smi` → Windows DXGI → Apple 统一内存，逐层探测）；显存不足或无法探测时**自动退化为单进程**，不会为了并发牺牲稳定性；
- **并发转写**：批量队列里的多个文件会由多个推理进程同时处理，文件之间互不排队；工作进程**按需创建**、用完复用，单个短文件不会白付一次模型加载成本；
- **硬件不适用时自动保持单进程**：纯 CPU（引擎本就会用满所有核心）、显存不足、显存无法探测，以及**集成显卡**（与 CPU 共享内存带宽，实测并发反而更慢）都会自动退回单进程，不会为了并发牺牲速度或稳定性；
- **自动线程数**：不再固定 4 线程，默认按 CPU 物理核心数（4–16）决定，普通多核机器即可获得数倍提升；
- **不再降优先级**：高性能模式下推理进程以正常优先级运行，不再为了界面流畅牺牲吞吐；
- 设置页新增「性能」标签页：可查看检测到的硬件、当前生效的并发数与线程数，以及**为什么是这个档位**（例如「显存 24 GB，可容纳 3 个进程」）；并发进程数可选手动覆盖。

### 交互与界面

- 批量页改为**每文件独立进度**：多路并发时每行显示自己的百分比、完成勾选或失败标记，面板上显示「已完成 / 总数 · 同时 N 个」；
- 模型设置里的线程数旁新增「自动」开关，与设置页共用同一份配置；
- 进度上报按任务区分：批量并发时各自更新自己的进度条，窗口/任务栏进度取所有在途任务的平均值（此前多任务会互相覆盖）。

### 可选：长文件分片并发（默认关闭）

设置 → 硬件加速 → 性能 里新增一个**默认关闭**的开关：超过 8 分钟的音频会先用 ffmpeg 检测静音、把切点吸附到静音处（找不到静音则等分），再交给多个进程同时转写，最后按时间偏移合并，避免从词中间切断；仅对 Whisper 系模型生效，开启说话人分离时自动关闭。

之所以默认关闭：在共享显存的显卡上实测分片反而更慢（0.56x），且切点附近的措辞会发生可观察的变化；换到显存充足的独显时可以打开它把单个长文件的耗时摊到多个进程上。

### 修复

- 中止转录改为**一次性共享信号**：多路并发时不再出现多个监听器同时杀进程的竞态；
- 应用退出时会清理**全部**推理进程（此前只记录一个 PID，多个工作进程可能残留）。

## 已知问题 / 升级说明

- 多进程并发会让显存占用按进程数增长：显存较小时会自动只用单进程，也可以在「设置 → 硬件加速 → 性能」里手动把并发数固定为 1；
- 集成显卡（共享显存）默认保持单进程 —— 实测并发会更慢；如确需并发可在同一页面手动指定进程数；
- 长音频分片默认关闭：切点依赖音频中的可检测停顿，且切点附近的措辞可能与整段转写不同；
- macOS 包未签名 / 未公证，首次打开若被 Gatekeeper 拦，右键 →「打开」即可。
